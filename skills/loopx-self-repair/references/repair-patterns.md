# LoopX Self-Repair Patterns

Use this file as a compact diagnosis table. Add a row whenever a real incident
teaches a reusable control-plane lesson.

| Pattern | Symptoms | Evidence To Read | Likely Root | Durable Repair |
| --- | --- | --- | --- | --- |
| `task_lease_generation_aba` | A lease is released or expires, the same todo is acquired again, and an older execution key/version can renew, release, or complete the new owner generation; a remote provider may show healthy monotonic storage generations while the LoopX fence repeats. | First and second acquire payloads, terminal lease record, full `(idempotency_key, version, lease_epoch)` fences, stale writeback result, provider generation, and release/re-acquire crash boundary. | Terminal release deleted the only per-todo generation record, so acquire rebuilt version 1; key-only mutation also made the CAS version optional and let execution-key reuse bypass no-ABA. | Keep provider generation opaque. Under the existing per-goal lock, atomically retain one inactive terminal lease record; advance authority-owned `lease_epoch` only for a new ownership generation and keep CAS `version` monotonic across every mutation. Require the current key/version pair for renew, transfer, release, and terminal writeback, reject immediate reuse of a retired key, and cover local CLI plus a live provider chain. |
| `task_session_projection_gap` | The UI says work is running while the linked Session has no active Turn, or a monitor opens an unrelated task Session. | Goal state, Todo id, Session `channel_id`, active Turn, and typed-action receipt resource ids. | Generic Goal activity was counted as active execution, or the UI joined Sessions by Goal id without the Todo id. | Count execution only from an active Turn, join task Sessions by Todo id, and create or resume a dedicated `task.<todo_id>` Session before an immediate monitor run. Cover idle resumable Sessions and multiple Todos under one Goal. |
| `author_owned_blocking_review_unrepresentable` | An author-owned PR receives a complete exact-head blocking review, but GitHub rejects self-`REQUEST_CHANGES` and the PR queue continues to classify the `COMMENTED` fallback as missing or malformed. | Published review state/body/title, exact review commit, machine English verdict, five required Chinese headings, and `review_conclusion.invalid_reasons`. | The review contract defined an author-owned no-blocker fallback only, so the GitHub identity restriction made a blocking conclusion impossible to encode; loose English verdict prose could also disagree with formal state. | Define separate exact `COMMENTED` titles for author-owned approval and request-changes outcomes, require a line-starting typed English verdict, validate title/verdict/state alignment, read the rendered review back at the exact head, and cover approval, blocker, untitled, and mismatched-state cases. |
| `state_projection_gap` | `quota should-run` says `should_run=true` or `must_attempt=true`, but user and agent open todo counts are both zero while `Next Action` still contains executable work. | quota payload, active state `## Agent Todo`, `## User Todo`, `Next Action`, `refresh-state` warnings. | Active state prose has drifted away from machine todo projection. | Expand executable prose into `- [ ]` agent todos, add refresh-state warning/smoke if projection missed it. |
| `selected_todo_continuation_projection_gap` | Quota selects the correct runnable Todo, but a later turn repeats completed implementation or follows a stale global `Next Action` instead of the Todo's latest bounded continuation. | `selected_todo`, selected Todo metadata, active-state `Next Action`, evaluator feedback, next-turn tool trace. | Compact Todo projections retained identity and routing fields but discarded the current note before selection, or kept stale durable action prose beside the selected Todo on the hot path. | Project one bounded, secret-screened `continuation_hint` from the selected open advancement Todo's current note or explicit suggested action. When that selection supersedes durable action prose, omit the shadowed prose from the default CLI packet and retain it behind the explicit detail path; do not copy raw evidence or require every intermediate step to write state. |
| `user_todo_projection_gap` | `interaction_contract.user_channel.action_required=true` or open user todos exist, but heartbeat/final message only says "owner gate" or does not name the concrete decision. | quota payload `interaction_contract`, `user_todo_summary`, active state user todos, recent final messages. | User-channel projection or agent final-response rule is too vague. | Fix prompt/projection so required user todo/question is surfaced; only say "具体 user todo 未投影" when action is required but absent. |
| `lark_inbox_priority_projection_gap` | A configured bot has a pending direct question or mention, but quota/status exposes only a static drain command and ordinary monitor/advancement work runs first. | local-private inbox counts, content-free oldest-pending age, `goal_boundary.capabilities.lark_event_inbox`, `work_lane_contract`, source-thread reply/readback receipt. | Inbox availability was modeled as a prompt reminder instead of a schedulable urgency read model and priority lane. | Project content-free pending/question/mention counts plus oldest age; make `reply_due` preempt ordinary work, then require durable effect, exactly one idempotent source-thread reply with readback, and ACK. Never project message bodies, ids, senders, or private paths into quota/status. |
| `lark_collector_profile_binding_gap` | A `configured_chat_all` inbox promises complete chat capture, but only some messages arrive or the collector and reply paths observe different bot apps; a non-mention present in bounded source history never reaches drain. | ignored collector/inbox config shape, generated service argv with values redacted, effective Lark CLI profile identity, inbox counts, bounded source-history presence, and exactly-once drain/ACK receipt. | The host collector invoked `lark-cli event consume` through the machine default profile while the reply path used a registered project profile; chat filtering and urgency classification were correct but applied to the wrong event stream. | Require an explicit non-default collector profile, or reuse the enabled reply sender profile; reject collector/reply mismatch, place `--profile` before every live collector event command, expose only content-free binding provenance, and cover non-mention ingest plus restart-safe dedupe/ACK. |
| `reviewer_reader_auth_misclassified_as_identity_drift` | A reviewer sink has explicit user-reader and bot-sender bindings, the sender bot remains healthy, but an unavailable reader user credential is reported as an identity mismatch and the agent starts rewriting profiles instead of requesting login. | Goal-default sink shape with profile values redacted, content-free `auth status --verify` availability for the configured reader and sender, provider call count, and secondary notification blocker. | Runtime user authentication availability and static profile-binding validity were collapsed into one identity-mismatch blocker. | Preserve the two explicit bindings; return a content-free reader-auth-required blocker, project the existing scoped login action, and perform zero destination reads or sends until user authentication verifies. Cover unavailable reader auth with a focused sink smoke. |
| `normal_no_user_todo_misflagged` | `action_required=false` and user open count is zero, but the agent reports a state projection fault. | quota payload and user todo summary. | Rule over-applied the "todo not projected" fallback. | Allow "无用户待办/无需通知"; update heartbeat/prompt smoke if needed. |
| `todo_no_followup_global_terminal_overreach` | A completed scoped Todo records `done + no_followup`, but `refresh-state --repair-delta-kind no_followup` becomes `replan_noop` because unrelated advancement or long-running monitor Todos remain open. | rejected repair-delta claim, complete Agent Todo projection, scoped Todo metadata, and the latest local no-follow-up completion. | The repair-delta validator reused Goal-level terminal-frontier completeness to validate a Todo-local closure. | Keep Goal `terminal_no_followup` strict, but validate repair-delta no-follow-up against the latest scoped completed Todo in a complete parser projection; reject other-agent, continuation-required, malformed, or truncated evidence and keep the emitted Todo evidence bounded. Cover the real CLI path with an open monitor regression. |
| `terminal_settlement_ordering_gap` | Final Todo completion succeeds, then the matching refresh or spend is rejected because the Goal is already terminal; different hosts may expose different closeout orders or retry the material effect. | Typed settlement plan and effect identity, Todo completion event, accountable refresh and spend receipts, Turn journal phase prefix, and host task-body projection. | Final `no_followup` was modeled like ordinary pre-settlement Todo completion even though it mutates Goal terminal state and activates the strict no-more-spend guard. | Keep Goal terminal guards strict. Treat ordinary successor completion as Todo lifecycle work, but make final `no_followup` a conditional post-spend terminal closeout under the same effect identity. Require matching writeback and spend receipts at the mutation boundary, prove the closeout event itself carries `no_followup`, and journal it so closeout-only retry cannot repeat writeback or spend. Cover CLI, visible Goal, Codex App, Turn driver, adapter order, failure short-circuit, and replay. |
| `runtime_capability_user_gate_overreach` | A missing launcher/runtime capability such as `network` becomes `capability_gate.action=ask_owner`, `requires_user_action=true`, or a user notification even though no credential, protected access, or production authority is needed. | quota `capability_gate`, heartbeat `--available-capability` inputs, launcher/runtime observations, interaction contract user channel. | Capability availability and permission authority were collapsed into one owner-held class. | Keep runtime provisioning gaps in the agent repair lane, require truthful runtime observation before declaring availability, and reserve `ask_owner` for credentials or protected/production authority. Cover all-blocked and mixed-capability cases with capability-gate and monitor smokes. |
| `visible_goal_dynamic_capability_projection_gap` | A visible Goal session proves a runtime capability such as `network` at a real callsite, but later continuations keep running the activation-time quota command without that capability and repeatedly enter `capability_bridge_repair`; a bounded host tool result truncates before the re-entry packet; or a same-turn re-entry selects a newly runnable Todo and conflicts with the heartbeat receipt already bound to the admitted Todo. | Activation-time capability list, later real-callsite observation, complete versus host-captured quota byte counts, byte offset of `runtime_capability_reentry_v0`, quota guard and follow-up argv, capability-gate result, heartbeat receipt settlement identity, and re-entry selected Todo. | The CLI decision surface lacked a typed re-entry packet, emitted it after diagnostics larger than the host capture budget, or recomputed Todo priority without treating the committed same-turn settlement identity as an immutable selection binding. | Keep the Goal prompt stable. Return the real-callsite-gated re-entry packet near the beginning of JSON CLI output; after verified re-entry, preserve observed capabilities in generated follow-up actions and prefer the receipt-bound Todo when it remains runnable. Fail closed on an unavailable bound Todo or an explicit conflicting Todo request. Never persist observations as grants. Cover blocked and bounded-capture packets, successful re-entry inheritance, owner-capability exclusion, receipt-bound replay, and explicit conflict. |
| `blocked_priority_fallback_hidden` | A core P0 path is user-gated, safe P1/P2 fallback runs, but the user is not told what blocked the P0 path. | quota `safe_bypass_allowed`, active priority stack, final heartbeat text. | Fallback execution hid the higher-priority blocked item. | Report concrete blocker plus fallback progress; expose `blocked_priority_fallback` in state/payload if missing. |
| `boundary_projection_gap` | `recommended_action` asks for work in a scope that is absent from `goal_boundary.write_scope`, such as runner edits blocked by repo-only scope. | quota `recommended_action`, `goal_boundary.write_scope`, authority/owner decision records. | Checkpointed owner decision did not project into current write boundary. | Repair boundary projection or ask controller/user; do not consume repo-only handoff steps that cannot touch the needed scope. |
| `public_surface_internal_context_leak` | Public docs, examples, fixtures, catalogs, README links, PR descriptions, or shipped evidence contain internal planning labels, meeting/reporting context, local-only status narratives, private operator framing, raw coordination details, or references to ignored local artifacts. | `git diff --stat`, `git diff --name-only`, `git grep`/`rg` over tracked public surfaces, docs indexes, fixture schema names, PR refs/history if already pushed, `.gitignore`, `.local` target path. | The agent treated a public artifact as durable memory for private planning, or generalized too late after internal context had already entered tracked history. | Move private planning to `.local` or another ignored state store, rewrite public text into generic product/maintainer language only when it is truly reusable, scan current public heads and PR refs, add a user/support gate if pushed read-only refs or cached views still expose the context, and record a concrete prevention todo before resuming feature work. |
| `periodic_report_editorial_contract_gap` | A periodic-report artifact claims operational context is collapsed, but the first real hosted report puts normalized-document parity, renderer/digest details, delivery receipts, archive-provider canaries, or other process narration in the hero or primary sections; a later readability pass may instead delete primary facts, omit supporting facts from copied text, or leave controls untranslated even when the profile language is set. A hosted shell may also expose supporting metadata or fail direct section hashes after dynamic mount. | Normalized document item kinds and visibility, compiled editorial lineage, primary and supporting item counts, original-to-rendered fact checklist, renderer `content_policy`, Markdown/HTML completeness, localized hosted DOM first viewport, initial hash position, source snapshot refs/digests. | Audience versus operational content was a prose convention instead of a normalized document contract, and readability was treated as deletion rather than information hierarchy; an authored hero summary could bypass item visibility, and language metadata did not own the built-in UI vocabulary. The host may also re-render the document without preserving renderer visibility semantics. | Compile hero summaries only from typed primary outcomes, risks, and next actions, record exact item/field lineage, and make renderers reject authored or stale summaries; preserve audience facts through bounded named detail rows; require runtime and delivery-receipt items to be supporting; collapse them in HTML and retain them in a labeled Markdown appendix; localize built-in controls from the profile language; validate source-to-artifact counts and representative facts; publish HTML artifacts without re-rendering or validate presentation parity; restore section hashes after mount; treat mutable source links as navigation rather than frozen evidence. |
| `dashboard_visual_acceptance_gap` | A dashboard passes document-level horizontal-overflow checks and its first viewport looks correct, but narrow cards or fixed-column tables clip internally, mutable text makes the same stable Todo appear twice, or a requested live source briefly renders synthetic example data. | Dual-size screenshots after live data settles, per-panel `scrollWidth` versus `clientWidth`, rendered Todo keys grouped by goal/role/stable id, and the initial loading/error DOM before a live response succeeds. | Visual acceptance checked only the document root, Todo identity included mutable display text, and the initial payload was treated as valid content while an explicit source was still loading. | Use responsive panel columns sized for their widest durable content; assert internal overflow on named high-risk panels; deduplicate by goal, role, and stable Todo id while retaining historical-only records; and render an explicit loading/error state until the requested live source succeeds. Cover the real long-evidence and same-id/different-text cases in a browser smoke. |
| `dashboard_status_hot_path_audit_gap` | The dashboard remains on its initial loading state for several seconds even though it has only a few Goals, and changing the status display limit has little effect. | Browser time-to-first-workspace, direct `/status.json` timing, `collect_status` profile, scanned-file count, regex-call count, and Git subprocess count. | The status read model runs repository-wide publication or private-boundary audits synchronously on every first-screen request. | Keep Goal, Todo, Agent, and runtime projections on the status hot path; defer the repository-wide public-boundary scan with an explicit machine-readable state; preserve the complete scan in `loopx check`; and cover both routes with focused tests plus a real status-endpoint timing probe. |
| `content_layout_sequence_acceptance_gap` | A carousel passes independent per-page density checks, but the cover is not the density peak or interior pages remain visibly sparse. | Typed layout plan, selected template `page_sequence`, renderer measurement packet, per-page densities, and `layout-check` failures. | Acceptance modeled each page in isolation and omitted sequence-level cover prominence and interior compactness defaults. | Keep project-specific narrative rules in the writing adapter, but make built-in templates require a cover first, a first-page density maximum, and an interior density floor; lock low-interior and denser-than-cover cases with focused negative smokes. |
| `shared_adapter_local_path_leak` | A shared adapter projection, such as Lark Kanban sync, would write an absolute local checkout, runtime, active-state, raw-log, or artifact path into a remote/shared row. | adapter dry-run payload, generated record values, docs boundary section, public/private scan. | Adapter reused local executor context as shared control-plane metadata. | Strip or replace the local path at the adapter projection layer, add a focused smoke that rejects the path, and only store explicit worker launch context when the row was authored for that purpose. |
| `peer_workspace_boundary_gap` | A peer edits or prepares repository changes from a non-git directory, unrelated worktree, or checkout that violates the selected task/repository isolation policy; a cross-repository repair may also be misclassified against the goal repo. | `agent_identity`, selected todo `task_repository` and write scopes, goal `repo`, current git origin/worktree/root, quota payload, heartbeat prompt commands, AGENTS worktree policy. | Workspace safety was inferred from identity labels, prompt text, or the goal repo alone instead of the selected task and `quota should-run`. | Add or repair `agent_workspace_guard_v1`; use a credential-free first-class `task_repository` only for genuine cross-repository tasks, and require a matching linked worktree. Block delivery and spend until the peer moves to a compliant worktree and reruns the guard with the same `--agent-id`. Keep the goal repo fallback and do not treat the field as scope or write authority. Read-only and monitor-only work should not be blocked merely by identity. |
| `monitor_successor_routing_gap` | A material monitor poll creates a natural-language `advance` successor for another repository, but the child has no repository, action, continuation, capabilities, stable target, or creation receipt; quota then routes plausible work without a safe workspace contract. | Parent monitor metadata, `quota monitor-poll` argv and artifact, child Todo metadata, rollout event successor ids, selected Todo workspace guard. | The agent extended a bounded observation into standing work, while the monitor-poll successor API accepted only text and an optional claimer and discarded typed routing. | Retire the unintended monitor/vision. Require explicit action semantics for every monitor-generated agent successor and explicit successor repository when the source monitor is repository-bound; carry optional execution capabilities, default continuation to `independent_handoff`, and derive a stable transition target when none is supplied. Record compact successor ids and routing receipts in the monitor artifact and rollout event. External-repository work must re-enter through that typed Todo rather than prior observation prose. |
| `delivery_workspace_causality_projection_gap` | A validated delivery is written in one worktree, but `refresh-state` or `spend-slot` is attempted from the goal repo, a canonical checkout, or another repository; the workspace guard correctly rejects accounting and the agent must discover the right invocation by trial and error. | Latest unspent accountable run `delivery_workspace`, selected Todo `task_repository`, refresh command cwd or `--delivery-workspace-path`, spend command cwd, `workspace_guard`, and the generated `interaction_contract.cli_channel`. | The fail-closed accounting guard owns the invariant, but the machine interaction contract exposed only generic refresh/spend commands and omitted the causal workspace requirements. | Preserve the guard. For spend-capable selected Todos with an explicit `task_repository`, project compact `delivery_workspace_causality_v0`: refresh from the producing workspace or pass its explicit delivery path, then spend from the recorded accountable workspace. Omit it from default and no-spend hot paths. |
| `material_monitor_workspace_settlement_gap` | A repository-bound material monitor poll records validated progress and a durable writeback receipt, but `quota spend-slot` rejects settlement because the monitor event has no delivery workspace and the matching `refresh-state --delivery-workspace-path` is treated as an ordinary idempotent replay. | Turn-scoped settlement identity and receipts, selected Todo workspace causality, material monitor run, matching refresh-state result, and spend failure. | Material monitor writeback became accountable before refresh-state could attach the required independent-worktree snapshot, while replay handling made the first durable receipt terminal even when its workspace causality remained incomplete. | Keep ordinary receipt replay idempotent. When causality says a workspace is required, the prior writeback has none, and the caller supplies an explicit validated workspace path, let refresh-state append exactly one supplemental causal record; replay that supplement idempotently and require spend to validate the recorded repository/worktree. Cover the no-path no-op, one supplement, supplement replay, and final spend. |
| `codex_app_ssh_host_loop_misclassification` | Codex App is connected to a remote project over SSH and has no automation tool, but onboarding or quota still requires heartbeat receipts, RRULE mutation, or a local-scheduler handoff. | exact host surface and agent type, available host tools, scheduler execution context, activation packet, generated task body, quota source, and usage summary classification. | Desktop Codex App and Codex App over SSH were collapsed into one host profile even though only the former owns heartbeat automation. | Add an explicit `codex-app-ssh` agent type and `codex_app_ssh_goal` runtime profile owned by the interactive agent CLI loop; activate one visible `/goal <task_body>` within the host character budget, omit heartbeat/RRULE instructions and receipts, account the validated run with `source=visible-goal`, and do not classify that spend as automation. Cover the generated command by parsing it through the real CLI. |
| `codex_app_ssh_quiet_continuation_storm` | A visible SSH Goal reaches `monitor_quiet_skip` or another unchanged wait, but the host immediately starts another model turn, repeats the same user notice, and never reaches a bounded pause. | typed scheduler execution context, `scheduler_hint.unchanged_poll`, generated visible Goal body, consecutive quota/monitor rows, and host Goal status. | The SSH runtime was typed as `agent_cli_loop`, but scheduler limits covered only local, CLI TUI, and Claude runtimes; the prompt prohibited RRULE mutation without connecting the SSH path to Codex `/goal` blocked state. | Project a `codex_app_ssh_goal` unchanged-poll limit while sharing Codex CLI's native Goal contract. At the third unchanged blocked turn, rerun quota once and call `update_goal(status=blocked)` if unchanged; do not spend or complete LoopX. Resume only through user `/goal resume`, then rerun quota. Cover both native Goal profiles, the compact packet, and generated CLI path. |
| `goal_phase_handoff_drift` | A visible or managed Goal completes one bounded phase, then the agent starts a successor host Goal for screening, implementation, review, or another ordinary phase even though the registered objective remains active. | generated Goal task body, typed host contract, active vision and todo frontier, host Goal ids, recent run history, and the user correction. | The prompt described bounded delivery segments without distinguishing them from the host Goal lifecycle, so phase progress was misread as a new Goal boundary. | Keep one activation as owner of the registered Goal until terminal; state that a bounded segment is internal progress, project `goal_lifecycle_scope=registered_goal_until_terminal` and `phase_handoff_allowed=false`, and cover both Managed Agent and visible Goal prompt families. Use a fresh Goal only for a materially different objective or an explicit recovery/test boundary, not ordinary phase continuation. |
| `host_native_goal_command_collision` | Adapter docs or onboarding imply that LoopX shell commands, MCP tools, and a host's native slash commands share one namespace; a user expects native `/goal` or `/goal-pro` completion to update LoopX, or starts both loops for the same task. | exact host slash help, adapter launch argv, exposed MCP tool list, project binding, and both host-native and LoopX goal states. | “First-class host surface” was described without naming the separate command namespaces and lifecycle owners, or an execution mechanism such as Arrangement was overstated as a separate Goal product semantic. | Publish an explicit command matrix; state whether the adapter invokes any native Goal mode; describe native strict variants as their shared Goal lifecycle plus the exact additional completion gate, with delegation named as its enforcement mechanism; choose exactly one outer lifecycle owner per task; require an explicit result/writeback mapping before using a native Goal as an inner executor. Never infer LoopX completion from host-native terminal state. |
| `host_native_goal_activation_gap` | An adapter launches a normal headless prompt and is described as autonomous long-running Goal execution, but the host slash command is TUI-owned, no model Goal-creation tool or app-server Goal mutation is invoked, and no scheduler launches another bounded turn. | host CLI help, model tool contract, app-server Goal methods, adapter launch argv and prompt, native Goal readback, scheduler ownership, ignored runtime journal, and agent-scoped writeback evidence. | Persistent control-plane state, native host Goal continuation, and repeated external process invocation were collapsed into one “long task mode.” | Name all supported Goal activation paths and their authority; state which one the adapter actually calls; never treat a long prompt as native Goal activation. For deterministic managed native Goals, have the outer controller create/read the host Goal through its machine API, start or resume the first turn, persist only opaque thread/goal lineage plus objective digest, require the exact verifier-backed terminal event for strict mode, block model-visible MCP and same-goal CLI lifecycle writes until that proof, and reconcile delivery/todo/quota phases against scoped evidence before retrying. Keep one outer lifecycle owner. Otherwise describe each run as bounded and require an explicit external scheduler for repetition. |
| `implicit_review_route_drift` | `todo complete` invents a default reviewer, routes completion by an agent profile, or blocks the completing peer without an explicit review request. | failing `todo complete` preview, successor continuation policy, todo claim metadata, generated heartbeat prompt, todo lifecycle smoke. | Review ownership survived as an identity-level parent/default handoff instead of task policy. | Use typed continuation: ordinary `independent_handoff` is non-blocking, `same_agent_non_delivery` stays with the peer, and only explicit `review_handoff` to a different registered peer creates a blocking dependency. Profiles must not supply an implicit reviewer. |
| `nonblocking_pr_review_continuation_gap` | A validated feature PR is waiting for human review and the same agent has independent runnable work, but the source todo remains blocked or the generated user todo becomes `user_gate`, so quota stops normal delivery. | source completion command, generated user/agent todos, user todo `task_class`/binding/gate scope, PR monitor, quota interaction contract, branch base topology. | `--next-user-todo` defaulted to a blocking gate and the workflow treated review latency as merge authority; no explicit reminder-versus-gate choice was recorded. | Complete the feature slice, derive a bound `user_action` with `--next-user-task-class user_action`, keep a runnable agent successor, and add a separate `continuous_monitor` for PR lifecycle readback. Use a stable integration branch when stacking experimental feature PRs and reserve `user_gate` for the exact aggregate merge/release/launch or protected authority boundary. Cover the generated todo metadata and eligible quota path in the todo lifecycle smoke. |
| `nonblocking_review_empty_frontier_replan_gap` | A bound `user_action` remains open after a feature PR, no runnable agent successor exists, and two bounded stalls are visible, but status still reports `operator_gate` or the replan only records prose. | active-state user/agent todo summaries, `waiting_on`, run-history stall evidence, replan obligation `todo_actions`, execution/interaction contracts, refreshed repair delta. | Active-state routing required an existing agent todo before treating `user_action` as non-blocking, and empty-frontier replans did not require concrete todo writeback. | Keep pure `user_action` as a visible non-blocking notice even on an empty agent frontier. After the stall threshold, require `autonomous_replan_required` to create and claim a runnable agent todo and record `runnable_todo_set`; allow terminal no-follow-up only with closure evidence. Preserve `user_gate` precedence for exact authority boundaries. |
| `repeat_vision_wait_ack_gap` | Two exact blocked-successor stalls correctly trigger replan, but a maintenance-only continuation appears to close the obligation while a `repeat_until_closed` vision still has no evidence-linked path outcome; later heartbeats repeat the same wait cycle. | active agent vision advancement policy, blocked-successor frontier identity, current obligation id, host-projected coverage ledger, typed progress observation, current runnable successor ids, and semantic receipt. | Replan validity considered a caller-supplied delta label instead of the obligation's typed outcomes and current state. | Require an accepted semantic delta bound to the exact current obligation. A vision-derived duty accepts a fresh evidence-linked vision path, new evidence-backed blocker, or coverage-backed terminal; a successor id is accepted only when current state proves it runnable, and maintenance-only continuation never closes the vision duty. Cover repeat/as-needed routing and stale-obligation identities. |
| `future_monitor_heartbeat_liveness_overreach` | A valid future-scheduled monitor repeatedly enters `frontier_exhausted_monitor_lane` or `dead_monitor_repeat` even though it is not due and no real monitor execution occurred. | generated heartbeat guard command, trigger `current_time_iso`, quota `heartbeat_receipt`, monitor Todo `next_due_at`, run-history `quota_monitor_poll` rows, concrete Todo/target identity, and monitor mode. | Future wait state was collapsed into empty-frontier exhaustion, while distinct heartbeat turn ids were treated as monitor executions and lowered the dead-monitor threshold. | Add typed `future_monitor_wait` and `due_monitor_execution` frontier rules. Keep future monitors quiet/no-spend until due; count `dead_monitor_repeat` only from unchanged due/external executions carrying a concrete Todo or target identity. Heartbeat turn ids remain idempotency/liveness evidence and never reduce the real execution threshold. |
| `replan_context_delivery_gap` | A replan obligation is visible, but a weak protocol-following model ignores or mis-executes a manual evidence-log read ritual, then spends turns debugging ACK/read order instead of choosing a new direction. | current obligation id, host-projected `replan_context_v0`, compact coverage ledger, delivery receipt, typed action packet, selected model tool action, semantic writeback receipt, and successor turn boundary. | Evidence access was modeled as an agent CLI obligation even though the control plane already owned the ledger; read execution and semantic use were conflated. A separate Todo-add then refresh ACK also let the model execute the successor in the replan turn. | Have the host prefetch and project bounded evidence coverage into quota. Treat the delivery receipt as context delivery only; require the model's real next action to produce an accepted typed semantic delta bound to the current obligation. When the delta is a runnable successor, bind the exact obligation on the Todo write itself and return `end_current_heartbeat`; do not require a second ACK or run the successor in that turn. Keep evidence-log as the durable chronology and optional drill-down, not as a closeout gate. Cover real quota→model action→Todo/refresh CLI behavior plus missing/wrong obligation identity. |
| `replan_meta_successor_churn` | An autonomous replan repeatedly adds and completes obligation-bound advancement Todos whose only action is to replan, re-arm, wait for the host, or report no new direction; Todo count grows while executable targets and evidence do not. | current obligation and acceptance gaps, generated replan action packet, bound Todo `action_kind`/`target_key`/Explore refs, semantic ACK, Todo lifecycle, and compact progress fingerprints. | A planning instruction was compiled into a runnable successor command, while Todo authoring and ACK validation treated obligation identity alone as proof of executable semantic change. | Generate a successor command only from a concrete bounded frontier with a typed action and stable target.
